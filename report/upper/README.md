# 상체(몸통 3자유도 + 오른팔 4자유도) 인공근육 설계 — 입력·가정·결과 (2026-11-03)

하체 설계(근육 8개, `report/`)와 같은 파이프라인을 설계 공간만 바꿔(`report/design_space.py`) 돌렸다.
입력 정본은 이 폴더의 `tasks.csv` 다. 한 줄 = trial 하나 = (IK, ID, 질량, 키, 과제, 손 하중).

용어 (2026-11-05 정함): 케이블 하나가 각 관절에 토크를 나눠 거는 비율 V 를 **관절 배분비**(예전 "방향"), 그 비율로 낼 수 있는 최대 세기 c 를 **토크 용량**(N·m, 예전 "용량"), 공간에서 케이블이 지나가는 방향을 **케이블 방향**이라 부른다. "방향"이 두 뜻으로 쓰여 헷갈려서 바꿨다. 코드의 변수·파일 이름(`V`, `design_directions`, `dir_err`)은 그대로다.

"서서 균형"은 걷기·들기 안의 직립 구간으로 대신한다. 따로 서기 데이터를 넣어도 몸통 용량은 바뀌지 않는다(용량은 걷기·들기가 정한다).
균형 제어를 다룰 때 검증용으로 쓰고 싶으면 `tasks.csv` 에 `task=stand` 줄을 추가하면 같은 명령이 그대로 돈다.

## 2. 상체 토크를 지면반력 없이 구해도 되는 이유

팔·몸통 관절 토크는 그 관절 위쪽 분절의 운동과 손 하중만으로 정해진다. 지면반력은 다리와 골반 잔차에만
들어간다. Moore T048_seg26 에서 GRF 를 넣고/빼고 ID 를 돌리면 arm_flex 15.08 vs 15.08, lumbar 39.25 vs 39.25
N·m 로 소수점 둘째 자리까지 같았다(2026-11-02). 그래서 CARRT 처럼 힘판이 없는 데이터도 그대로 쓴다.
단, 상체 ID 는 좌표를 **6 Hz** 로 거른다(15 Hz 는 팔 토크에 99퍼센타일의 2~3배짜리 잡음 스파이크가 남았다).

## 3. CARRT 처리에서 둔 가정

- 마커 43개 → Rajagopal 마커셋 35개 이름 매핑(`tools/carrt_prepare.py` `MAP`). 어깨 마커(RSHO)가 삼각근 위라
  상완 길이는 팔꿈치–손목 비례로 잡았고, RDELT/LDELT 는 모델에서 torso 에 붙어 있어 humerus 로 옮겼다.
- 스케일은 축별 측정(골반 폭 ASIS–ASIS, 몸통 C7–PSIS 등)으로 했고, MarkerPlacer 가 파이썬에서 마커를 안 옮겨
  정적 IK 로 직접 놓았다(`place_markers`).
- IK 마커 RMS: 상자 1.8 cm, 나머지 3.0~3.5 cm (최대 9~13 cm). 계획 기준(RMS < 2 cm)보다 크다 — 팔 회전은
  마커 3개뿐이라 믿을 수 없고, 극단 자세(어깨 회전 −170°)는 IK 가 꼬인 프레임일 수 있다.
- 물체 질량(논문 표 3): 상자 0.52 kg **양손 반씩**, 찬 물병 3.79, 빈 물병 0.90, 찬장 0. 손 바디에 질량만 더했고
  관성·잡는 위치 오프셋은 없다. "Half Body" 폴더는 마커 20개뿐이라 안 썼다.
- 피험자 키는 Data.xlsx 에 없어 1.626 m 로 통일(세그먼트 치수에서 추정). 정규화는 질량×키 비율.
